# ג — Shoulder-node continuation

Status: spec updated to the shoulder-node formulation. Implementation may differ.

## Definition

- **Select:** current focus `(F)`.
- **Bound:** allocate intermediate node `M := alloc()` and successor `F^{+} := alloc()`.
- **Graph edges emitted:**
  1. `cont(F, M)`
  2. `carry(F, M)`
  3. `cont(M, F^{+})`
- **Seal:** set `F := F^{+}`.

## Notes

- `M` is an on-spine intermediate node, not metadata.
- The carry lands on `M`, not on `F^{+}`.
- Formal unary note: `ג` is unary. It does not select a needy recipient, and the medrashic giving-pressure is represented structurally by the carry landing on the intermediate shoulder node `M`. Any later support relation is handled by the existing VM's ordinary `supp` and `eff` rules. Therefore this implementation rejects dyadic recipient selection, introduces no extra operand or recipient slot, uses no pair-coupled execution rule, and adds no new edge types.
- `ג` remains unary.
- `ג` does not select a recipient.
- `ג` does not create a payload object.
- `ג` does not introduce new edge types.
- `ג` differs from `נ`: `נ` uses `carry(F, F^{+})`, while `ג` uses `carry(F, M)` with `M` strictly between `F` and `F^{+}`.
- Future resolution uses the existing `carry`/`supp` rules; `ג` adds no separate resolution mechanism.
